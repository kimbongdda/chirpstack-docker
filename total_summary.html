02 · 최종 권장 아키텍처

기본 원칙: 지역당 DLOS8N 1대 + 스타링크 1대. 각 게이트웨이가 독립적으로 한국 서버 Mosquitto(포트 8883 TLS)로 연결합니다.

02.5 · 데이터 흐름 — 단계별 쉬운 설명

위 아키텍처 다이어그램의 번호 ①②③④가 아래 각 단계에 대응합니다.

① 노드 → 게이트웨이 : LoRa 무선 신호

센서(노드)가 데이터를 라디오 전파로 쏩니다. Wi-Fi와 비슷하지만 전력을 훨씬 적게 쓰고 수 킬로미터를 날아갑니다.

  • 주파수 AS923-1 (923 MHz) — 베트남에서 허가된 주파수 대역입니다. 나라마다 다릅니다. (한국 922 MHz, 미국 915 MHz)
  • Spreading Factor (SF) — SF7~SF12. 숫자가 클수록 멀리 가지만 전송 속도는 느려집니다. SF9 기준 약 5 km.
  • AES-128 암호화 — 데이터가 공중을 날아다니므로 전송 전에 암호화합니다. 금융권에서도 쓰는 방식입니다. 게이트웨이는 암호화된 채 그대로 서버로 넘기며, 복호화는 ChirpStack 서버만 할 수 있습니다.

공중을 날아다니는 패킷 구조 (PHY frame) — 전체가 수십 바이트짜리 이진 데이터:

[ 헤더 1B ] [ 디바이스주소 4B ] [ 순서번호 2B ] [ 암호화된 센서값 ] [ 무결성코드 4B ]
   MHDR          DevAddr           FCnt          FRMPayload (AES)      MIC

② 게이트웨이 내부 : UDP :1700 (기기 내 통신)

DLOS8N 안에는 두 소프트웨어가 협력합니다:

  • Packet Forwarder — 라디오 칩에서 신호를 받아 JSON으로 정리
  • Gateway Bridge — 그 JSON을 받아서 서버 전송 형식(Protobuf)으로 변환

둘 사이는 UDP 포트 1700으로 연결됩니다. UDP는 "같은 기기 내부의 빠른 데이터 전달 방식"입니다. 인터넷이 아닌 기기 내부이므로 암호화가 필요 없습니다.

Packet Forwarder → (UDP :1700) → Gateway Bridge

{
  "rxpk": [{
    "freq": 923.2,          ← 수신 주파수 MHz
    "datr": "SF9BW125",     ← SF9, 대역폭 125 kHz
    "rssi": -85,            ← 신호 강도 (낮을수록 약함)
    "lsnr": 7.5,            ← 신호 품질 (높을수록 좋음)
    "data": "QAQ..."        ← 암호화된 센서 데이터 (base64)
  }]
}

③ 게이트웨이 → 한국 서버 : MQTT / TLS :8883 (Starlink 구간)

베트남 → 한국을 잇는 핵심 구간. Starlink 위성을 통해 날아갑니다.

  • MQTT — 가벼운 메시지 전달 프로토콜. "발행(publish)/구독(subscribe)" 방식. 게이트웨이가 메시지를 발행하면 한국 서버(Mosquitto)가 받아 ChirpStack으로 전달합니다. 카카오톡 채널에 글 올리면 구독자가 받는 것과 유사합니다.
  • TLS :8883 — 인터넷 구간 암호화. HTTPS와 동일한 방식입니다. (포트 8883 = MQTT + TLS 표준 포트)
  • Protobuf — 전송 데이터 형식. JSON보다 4~5배 작게 압축된 이진 형식입니다. 위성 통신은 대역폭이 제한적이므로 작은 형식이 유리합니다.

MQTT 토픽 예시:

as923/gateway/aabbccddeeff0011/event/up   ← 게이트웨이 업링크 (Protobuf)
application/app123/device/dev456/event/up  ← 최종 앱 데이터 (JSON)

④ 한국 서버 내부 : 복호화 + 디코딩 → JSON

ChirpStack이 순서대로 처리합니다:

  1. Mosquitto 브로커에서 Protobuf 수신
  2. AES-128 복호화 → 암호화된 센서 데이터를 읽을 수 있는 상태로
  3. 페이로드 디코딩 → 바이트를 실제 센서값(온도, 습도 등)으로 변환
  4. JSON 이벤트 생성 → Dashboard / API로 전달
권장 — CayenneLPP

표준 인코딩 형식. ChirpStack이 자동 디코딩하므로 별도 코딩 불필요합니다.

03 67 01 10  ← 온도 ch3: 27.2 °C
05 68 64     ← 습도 ch5: 50 %RH
커스텀 바이너리

바이트를 직접 정의. ChirpStack에 JavaScript 코덱 등록 필요합니다.

function decodeUplink(input) {
  return { data: {
    temperature:
      (input.bytes[0]<<8
       | input.bytes[1]) / 10,
    humidity: input.bytes[2]
  }};
}

최종 출력 — Dashboard / API가 받는 JSON

모든 처리가 끝난 후 사람이 읽을 수 있는 형태로 나옵니다. object 필드만 보면 센서값을 바로 알 수 있습니다.

{
  "deviceInfo": {
    "deviceName": "zone-a-sensor-01",
    "devEui":     "0102030405060708"
  },
  "object": {                         ← 최종 센서값 (여기만 보면 됨)
    "temperature_3":       27.2,      ← 27.2 °C
    "relative_humidity_5": 50.0       ← 50 %RH
  },
  "rxInfo": [{
    "rssi": -85,                      ← 신호 강도 (dBm, 낮을수록 약함)
    "snr":   7.5                      ← 신호 품질 (높을수록 좋음)
  }],
  "txInfo": { "frequency": 923200000 } ← 923.2 MHz
}
Dashboard 연동: Flask 대시보드는 application/+/device/+/event/up 토픽을 MQTT 구독합니다. object 필드에 이미 디코딩된 센서 값이 있으므로 별도 파싱 불필요.

지역 내 커버리지 확장이 필요할 때

한 지역 안에서 노드가 DLOS8N 직접 도달 범위 밖에 있을 경우의 선택지입니다. 지역마다 Starlink는 Border GW 1대에만 연결하면 됩니다.

1순위 — 추가 장비 없음

SF 올리기

노드를 SF10~SF12로 설정. 평지 기준 최대 15km 도달. 추가 장비·비용 전혀 없음.

2순위 — 권장

ChirpStack Gateway Mesh

DLOS8N 추가 설치 → Relay GW로 동작. 인터넷 불필요, 12V 전원만 있으면 됨. Border GW(Starlink)가 인터넷 처리.

노드 → Relay GW →(LoRa)→ Border GW → Starlink → ChirpStack
3순위 — 고비용

P2P 무선 브릿지

DLOS8N 추가 + Ubiquiti 브릿지로 IP 연결. 시야 확보 시 5~30km. Gateway Mesh 설치가 어려울 때 대안.

4순위 — AC 전원 필요

OLG02 리피터

LoRa RF 재전송, IP 불필요. AC 전원 또는 인버터 필요. 상용 전원이 있는 중간 거점에 설치 가능한 경우.

03.5 · ChirpStack Gateway Mesh 상세

핵심: Relay GW는 인터넷이 전혀 없어도 됩니다. 12V 전원만 연결하면 LoRa RF로 Border GW에 패킷을 전달합니다.
Border GW (지역당 1대)
  • Starlink에 연결 → ChirpStack으로 MQTT/TLS 전달
  • 일반 Gateway Bridge 설정 그대로 사용
  • Relay GW에서 오는 Mesh 패킷도 함께 수신
Relay GW (커버리지 부족 곳에 추가)
  • 인터넷 연결 없음 — 12V 전원만
  • 노드 업링크 수신 → LoRa로 Border GW에 재전송
  • 다운링크도 역방향으로 중계 (Border → Relay → 노드)
  • 멀티홉 가능 (최대 8홉)

전원 인프라 주의: Relay GW는 인터넷이 필요 없지만, 전원 공급 인프라는 Border GW와 동일하게 필요합니다. 설치 위치가 원격지라면 태양광 패널 + 배터리 + MPPT 컨트롤러 + 방수 함체를 Relay GW에도 별도로 구축해야 합니다. "인터넷만 없어도 된다"는 것이지, 무전원 동작은 불가능합니다.

05 · 한국 서버 설정 변경사항 요약

변경 필요

Mosquitto TLS (포트 8883): 인터넷에서 들어오는 MQTT 연결에 TLS 적용. Let's Encrypt 또는 자체 서명 인증서 발급 후 mosquitto.conf에 리스너 추가.
docker-compose.yml: 포트 8883:8883 추가, 인증서 볼륨 마운트 추가.
방화벽: 포트 8883만 외부 오픈. 8080, 5000은 내부 또는 VPN 전용 유지.

이미 완료

AS923 활성화: chirpstack.toml에 as923 이미 enabled. 베트남 AS923-1 주파수 별도 설정 불필요.
ChirpStack v4 운영 중: 게이트웨이 추가 등록만 하면 바로 수신 가능.
Dashboard: 기존 Flask 대시보드 그대로 사용 가능. 베트남 노드도 동일하게 표시됨.

07 · 구현 로드맵

1

한국 서버 준비

공인 IP 확인 → TLS 인증서 발급 → Mosquitto 8883 TLS 설정 → docker compose up -d → 방화벽 8883 오픈

2

DLOS8N 1대로 로컬 테스트

한국 서버와 같은 네트워크에서 DLOS8N AS923 설정 → Gateway Bridge → Mosquitto TLS 연결 확인 → ChirpStack에서 패킷 수신 확인

3

Zone A 파일럿 배포 (베트남)

첫 지역 DLOS8N + 스타링크 설치 → 태양광 연결 → 현장에서 한국 서버로 MQTT TLS 연결 확인 → 노드 ABP 등록 → 패킷 수신 검증 → SF별 도달 거리 실측

4

Zone B / C / D 순차 배포

동일 설정 복제 → 지역별 별도 MQTT 계정 적용 → ChirpStack에 게이트웨이 및 노드 등록 → 대시보드에서 전체 지역 모니터링 확인

5

커버리지 부족 지점 보완 (필요 시)

실측 후 음영 지역 파악 → SF 상향 우선 → 그래도 불충분 시 DLOS8N Relay GW + ChirpStack Gateway Mesh 추가 설치 (12V 전원만 필요, Starlink 불필요)

08 · 한눈에 보는 최종 결론

확정 사항
· 지역당 DLOS8N 1대 + 스타링크 1대가 기본 단위
· AS923-1 이미 활성화됨, 추가 설정 불필요
· 한국 ChirpStack 서버에 MQTT TLS(8883)만 추가하면 연결 가능
· 노드는 ABP + Unconfirmed Uplink 권장
· 기존 Flask 대시보드 그대로 재사용 가능
불가능 / 주의사항
· Dragino 제품 중 배터리 동작 LoRa 패킷 릴레이 → 라인업 없음
· DLOS8N UDP 프록시 → 지역 간 IP 연결 없으면 동작 불가
· Gateway Mesh Relay↔Border 링크도 LoRa → 에어타임 2배 소비
· Gateway Mesh DLOS8N 설치 → 공식 패키지 없음, 수동 빌드 필요
